# 前后吸取路径规划要求和限制

## 规划策略摘要（已实现）

**航点配置**：`config/ui_points_fast_mode.yaml`（标定导出，含每条路径的实际 wp 数、状态、target_id、motion_planner 与 UI 坐标）。规划器启动时自动加载。

**三阶段执行顺序（硬约束）**：

| 阶段      | 箱子                 | 说明                                                                |
| --------- | -------------------- | ------------------------------------------------------------------- |
| 1. 保底   | **4 号**       | path1 完整走完（1-1 吸取 → 1-2 → 1-3）→ 跨路径直达对应归还区放置 |
| 2. 第一行 | **0、1、2、3** | 必须全部完成后再进入阶段 3                                          |
| 3. 第二行 | **5、6、7**    | 第一行 4 个全部 pick+place 后才开始                                 |

**主任务组内排序**（第一行、第二行各自独立）：

1. 智力题种类（二次规划时，`quiz_type` 匹配优先，但不打破行序）
2. 路径距离 `abs(current_path - pick_path)`（**最近路径优先**；允许同种类箱子放置两次）
3. `box_id` tie-break

**移动规则**：

- path1 保底：仍依次经过 1-2、1-3 过渡航点
- path2–5 主任务：**不强制经过中间航点**；跨路径或同路径内 pick 后直达 place 航点（无 wp3 对齐等过渡）
- 航点 wp 索引与放置位置取自 `ui_points_fast_mode.yaml`（如 path2 放置 wp2，path3–5 放置 wp3）

**输出**（默认 `tmp/`）：

- `mission_plan.yaml` / `.json` / `.csv` — 逻辑七元组序列
- `mission_quintuple.yaml` — 五元组 `(path, wp, state, target_id, motion_planner)` 供行为树（仅 PICK/PLACE）
- `mission_plan.png` — 按 ui_points 标定坐标划线

## 航点标定工具（waypoint_editor_fr）

用于在 `场地俯视图.png` 上标定各路径航点的 UI 位置，并与行为树航点命名对齐。每条路径的航点数量**自由**（点完一条路径后点「本路径完成」）。

### 启动

```bash
ros2 launch legged_mission_planner_f_r waypoint_editor.launch.py
# 或
ros2 run legged_mission_planner_f_r waypoint_editor_fr
```

可选参数：

- `--ui-points-out`：ui_points.yaml 输出路径（默认 `config/ui_points.yaml`）
- `--mission-plan-out`：mission_plan_hardcoded.yaml 输出路径（默认写入 `legged_mission_bt/config/`）
- `--load-existing`：从已有 ui_points.yaml 继续编辑（若默认路径存在则自动加载）

### 操作流程

1. 在左侧输入路径号（如 `1`），点「开始」
2. 在场地图上依次左键点击航点，生成 `1-1`、`1-2`、…（红色小圆 + 标签）
3. 点「本路径航点设置完成」锁定该路径，继续下一路径
4. 全部完成后点「全部完成并导出」

### 输出文件

**ui_points.yaml**（`legged_mission_planner_f_r/config/`）— 供后续路径规划 UI 绘制：

```yaml
format_version: 1
planner_variant: front_back
field_image: 场地俯视图.png
coordinate_system: normalized_field_image
paths:
  1:
    - id: "1-1"
      norm_x: 0.537
      norm_y: 0.518
```

**mission_plan_hardcoded.yaml**（`legged_mission_bt/config/`）— 行为树 nav 航点命名模板，id 与 ui_points 一致，**x/y/yaw 留空**：

```yaml
nav:
  "1-1":
    frame_id: "map"
    x: null
    y: null
    yaw: null
```

> **注意**：当前 `WaypointRegistry` 要求 nav 航点 x/y 非空，因此坐标填充完成前**不能**将 `mission_plan_hardcoded.yaml` 作为 `waypoints_file` 直接启动 BT。map 坐标需用后续采集脚本写入。

### 目标架构 vs 当前实现

| 项       | 目标架构（文档顶部）                                   | 当前代码实现                                |
| -------- | ------------------------------------------------------ | ------------------------------------------- |
| 状态     | 0–3（识别/走点/吸取/放置）                            | 0–4（含 PICK_FRONT/PICK_BACK/PLACE_FRONT） |
| 规划输出 | 五元组`(path, wp, state, box_or_zone_id, motion_planner)` | `sequence[]` 含 target_box/target_zone    |
| 航点坐标 | BT 包存储，规划只传编号                                | 本包不导出 pose                             |
| 航点命名 | `P-W`（如 `1-1`）                                  | 航点标定工具已对齐                          |

## （一）基础规划（不启用智力题）

### 1. UI 标注

启动 `mission_base_plan_fr`（`base_plan.launch.py`）后弹出基于任务赛地图的 UI（`场地俯视图.png`、箱子与归位区图标）。操作手观察场上 8 个箱子，点击 UI 中物资种类后标注各位置。

- 食品/工具/仪器/药品种类编号：0、1、2、3（绿/灰/蓝/红）
- 四个放置区种类顺序可配置，默认 `[0,1,2,3]`，可选 `[3,2,1,0]`

**位置编号**（从右往左）：

```
放置区: 3  2  1  0
上排箱: 3  2  1  0
下排箱: 7  6  5  4
```

### 2. 机械条件

机器人向前/向后吸取与放置：**向后吸取、向前放置**。规划输出 `(path, wp, state)` 供行为树分支。

### 3. 路径与航点（4 航点）

| 路径        | 角色                 | wp1                         | wp2                        | wp3     | wp4                           |
| ----------- | -------------------- | --------------------------- | -------------------------- | ------- | ----------------------------- |
| **1** | 保底路径（仅走一次） | box4**PICK_FRONT(2)** | 走点(1)                    | 走点(1) | 走点(1)                       |
| **2** | 第 0 列              | 下排（保底后跳过）          | box0**PICK_BACK(3)** | 过渡    | zone0**PLACE_FRONT(4)** |
| **3** | 第 1 列              | box5 PICK_BACK              | box1 PICK_BACK             | 过渡    | zone1 PLACE_FRONT             |
| **4** | 第 2 列              | box6 PICK_BACK              | box2 PICK_BACK             | 过渡    | zone2 PLACE_FRONT             |
| **5** | 第 3 列              | box7 PICK_BACK              | box3 PICK_BACK             | 过渡    | zone3 PLACE_FRONT             |

**放置路径**：`box_type → zone_id`（由 `zone_types` 决定）→ `place_path = zone_id + 2`。

### 4. 机器人状态

| 状态 | 含义       | 使用位置         |
| ---- | ---------- | ---------------- |
| 0    | 智力题识别 | 启动区           |
| 1    | 纯走点     | 过渡航点         |
| 2    | 向前吸取   | 仅 path1 wp1     |
| 3    | 向后吸取   | path2–5 wp1/wp2 |
| 4    | 向前放置   | path2–5 wp4     |

### 5. 三阶段执行流程

1. **保底阶段**：启动区 → path1 wp1 吸取 box4 → path1 wp2–wp4 走点
2. **保底放置**：按 box4 种类到对应 path2–5 的 wp4 放置
3. **主任务**：先完成第一行（box 0/1/2/3），再完成第二行（box 5/6/7）

### 6. 移动规则

| 场景 | 行为 |
| ---- | ---- |
| 跨路径吸取 | 当前 wp → 目标 pick_wp 直接吸取 |
| 跨路径放置 | 当前 wp → 目标 place_wp 直接放置（无 wp3 对齐等过渡） |
| path1 保底 | 依次经过 1-2、1-3 过渡航点后跨路径直达放置航点 |
| path2–5 同路径内 | pick 后直达 place 航点，不强制经过中间航点 |

### 7. 主策略优先级

主任务组内（保底与行序硬约束不变）：

1. 智力题种类（二次规划时）
2. **最近路径优先**（`abs(current_path - pick_path)`）；允许同种类重复放置
3. `box_id` tie-break

### 8. 完整示例

输入：`box_types=[0,1,2,3,0,1,2,3]`，`zone_types=[0,1,2,3]`

```
(0,0,1) start
(1,1,2) pick box4 (type=0)
(1,2,1) → (1,3,1) fallback transit
(2,2,3) place box4 → zone0
(2,1,3) pick box0
(2,2,3) place box0
... 继续第一行 box1/2/3，再第二行 box5/6/7
```

## （二）智力题二次规划

基础规划与智力题规划已拆分为两个独立 launch，须**先基础、后智力题**。

### 启动流程

```bash
# 阶段 1：基础规划
ros2 launch legged_mission_planner_f_r base_plan.launch.py

# 阶段 2：智力题二次规划（自动等待，不可点击标注）
ros2 launch legged_mission_planner_f_r quiz_plan.launch.py
```

### 阶段 1 — 基础规划

- 操作手在 UI 标注 8 个箱子种类与 4 个归还区种类
- 点击「规划并导出」后输出全套文件到 `tmp/`
- 同时保存 `tmp/base_scenario.yaml`：

```yaml
box_types: [0, 1, 2, 3, 0, 1, 2, 3]
zone_types: [0, 1, 2, 3]
output_dir: .../tmp
saved_at: ISO8601
```

### 阶段 2 — 智力题规划

- 启动时加载 `base_scenario.yaml` 与已有 `mission_plan.yaml`（只读展示）
- **自动**订阅 `/mission/quiz_type` 并等待 **20s**（`quiz_mission_params.yaml`）
- 收到智力题种类：在主任务阶段将 **quiz 种类优先级置于最短路径之前**，但仍保持第一行全部完成后再第二行；覆盖导出全套文件（`plan_source: quiz`，启动步 `(0,0,0)`）
- **超时未收到**：不覆盖写入规划文件，保留基础规划输出；仍发布 `/mission/plan_ready` 触发 BT 转换

### 排序规则（二次规划）

组内 `(quiz_rank, distance, box_id)`：
1. 智力题匹配种类优先
2. 最近路径 `abs(current_path - pick_path)`
3. `box_id` tie-break

## （三）导出格式

- `format_version: 2`
- `planner_variant: front_back`
- `max_waypoint: 4`
- `switch_mode: fast_mode`
- `sequence[]`: `{path, wp, state, target_box, target_zone, box_type, zone_type, note}`

坐标解析由 `legged_bringup` 负责，本包不导出 pose。
